## 收尾问题

1. **握手仍把 WAIT_FAILED 当成“活着”。** 本轮把真实 `_handshake` 提取到模拟 API 环境，注入 `WaitForSingleObject=0xFFFFFFFF`，它仍返回 verified=True。应仅接受 WAIT_TIMEOUT 为存活，其他错误应记录并失败；需要新增失败回归。
2. **A1 判定未检查 sandbox_rc。** 当前记录确实是 rc=0，但判定函数没有该参数，因此未来探针在输出令牌与拒绝信息后异常退出仍可能算通过。应明确要求沙箱退出 0，以及普通对照等待完成和 GetExitCodeProcess 成功。
3. **兜底清理重新按 PID 获取终止句柄。** 本轮没有动用该分支；下一版应在握手时获取、验证并持有含 PROCESS_TERMINATE 权限的精确 HANDLE，清理直接使用该 HANDLE 并等待确认退出，避免重新按 PID 查找。
4. 错误捕获说明中提到 `k.get_last_error`，它不是对应 Win32 API。应明确使用 `WinDLL(use_last_error=True)` 后立即 `ctypes.get_last_error()`，或使用正确原型的 `GetLastError`；不要因旧捕获错误继续给出不准确归因。
