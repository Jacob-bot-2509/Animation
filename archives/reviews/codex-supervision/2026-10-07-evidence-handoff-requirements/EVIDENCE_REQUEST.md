依据用户 2026-10-07 指令：“明确告诉claudecode到底要那些证据链和材料”。本清单用于当前 holdout 历史缺口及独立验收；沿用 [等效证据规则](../2026-10-07-equivalent-evidence-policy/EQUIVALENT_EVIDENCE_POLICY.md)，不新增验收标准。

当前基线：391条候选、合格数UNKNOWN、36项历史字节缺口、数学范围关闭0项，UNCALIBRATED / CLOSED。先交下面三组准备材料；实际裁决、抽样及统计结果在相应条件落实后另交，不能预填通过。

## 一、36项缺口：从历史引用到内容范围的证据链

交付：gap-coverage.jsonl、coverage-proofs/、material-bindings.json。

每项必须连成以下链条：
\[
\text{历史引用/版本身份}
\longrightarrow \text{有绑定的替代材料}
\longrightarrow \text{完整内容或保守范围证明}
\longrightarrow \text{受影响的候选/核心/角色范围}
\longrightarrow \text{可复核的处理记录}.
\]

gap-coverage.jsonl 必须覆盖 [36个具名目标](TARGETS.json)，一版本一行。每行至少写：

| 字段 | 所需实际内容 |
|---|---|
| historical_reference | 原路径、历史声明SHA、引用清单SHA与定位；保留原声明的哈希口径，不把通用声明擅自改为raw SHA |
| route | A精确字节、B完整数学重建、C保守上界、D无题目/选题内容证明；未能确定则PENDING |
| substitute_bindings | 现有材料路径、实际raw SHA、字节数；Git提交/对象、规范化SHA另列 |
| proof_ref / covered_versions | 完整证明文件及SHA；证明明确覆盖哪些历史版本 |
| covered_content / residual_unknown | 覆盖的题干条件、过程、答案、生成内容或成员选择范围；尚未知的内容 |
| affected_scope | 被关联的数学记录版本、候选身份、核心或可能接触角色；未知写UNKNOWN，不写空集合 |
| disposition / review_receipts | 提议重建、保守隔离或排除；真实审查者、输入包SHA、时间、理由/回执；未审留空/PENDING |

同一个完整证明可覆盖多项，列出 covered_versions 即可，不要求写36份重复说明。不必追回每一份原件：无法恢复的部分可使用经证明的上界，或按可能已曝光保守隔离；字节缺口与资格风险分别记账。

### 27项筛选/清理材料

要交的是“历史生产器/运行 → 全部可能输入版本 → 数学输出或非内容证明”，不能只交来源日期。

- 绑定各运行可能使用的脚本版本、入口/参数、样本来源版本及现有日志。缺具体样本时，可取所有可能源版本的完整并集，证明它包含每个可能历史输入。
- 对results、HTML、README等可能含数学输出的材料：交完整输出/可重建记录，或证明全部可能数学内容的上界。只知道输入来自raw题库，不能自动证明生成输出范围。
- 对summary、steps、adapter配置等拟走D的文件：交历史特定生产器、schema/模板、实际输入及输出字段范围，证明没有题目、过程、答案、生成数学内容和成员选择信息。按文件名排除不成立。
- 用保守范围 \(B\) 时，须证明缺失内容 \(H\subseteq B\)；继续使用的候选 \(u\) 还须证明对全部相关 \(b\in B\)，\(u\not\sim_{\mathrm{core}}b\)。未能证明不同的成员保持隔离。

### 8项旧批次材料

7个旧JSONL和batch-02旧报告：交完整可逆变化链，覆盖被删除/改变的数学字段与各相关旧版本；或证明所有可能旧输出属于一个已绑定的完整版本并集/数学上界。

只有“before SHA + 当前after文件”不能重建旧过程；8个后继存在不能证明v2/v3/v4-final全部迭代。自编来源也不能证明与公开题池不同核心。已核验的后继文件直接引用，不再重做相同存在性报告。

要交其实际选择的完整成员和版本；找不回时，证明全部可能旧选择成员都包含于一个明确并集，并绑定并集各成员的完整数学内容。

## 二、从历史材料到391候选的数学核对材料

交付：historical-task-corpus.manifest.json、historical-task-corpus.jsonl、history-coverage-map.jsonl、candidate-qualification.pending.jsonl、review-input-pack.manifest.json。

- 完整数学任务：每个相关历史任务提供对象、全部假设/定义域/分支、完整目标、必要推导依赖、过程和答案；标明来源文件实际SHA、行/JSON定位、记录版本SHA及关联旧版本。数学错误保留原文，另附精确勘误，不静默覆盖。
- 历史覆盖映射：现役47训练记录/46核心、264草稿及其相关旧版、497现役行、296工作流对、B5、旧样本/输出等，各自映射到完整任务或明确的无相关内容证明/未知范围。重叠材料可引用同一份完整内容，但必须保留别名和全部相关版本映射；不用再复制75739份文件。
- 所有未知历史范围须能回指第一组的具体gap/proof/隔离决定；只做现役46核心比较不足以证明完整历史隔离。
- 原391候选按“原池SHA + 完整记录SHA”绑定；重复题号用既有别名区分。pending账本391行全部列入，不加题、不造数值变体、不通过删未知成员改善结果。
- 给实际审查者的输入包必须含完整题干、过程、答案、必要来源上下文及SHA。候选与相关历史任务比较采用原核心协议；文字分数、日期、自编声明、只看答案不能代替数学理由。

这一组首先是可审的材料，不要求Claude用自签标签替代独立结论。实际审查开始前落实第三组角色与接触记录。初审A由Codex按既有协议另行登记输入和开始；独立B和冲突C须实际落实。

随后交付 core-comparisons.jsonl 和 candidate-qualification.reviewed.jsonl：逐项保存双方独立理由、SAME_CORE / DIFFERENT_CORE / UNRESOLVED，冲突实际裁决；未审UNREVIEWED不得当阴性。共享核心的必要代表全部覆盖，成员与核心族隔离另有来源映射。数学表达使用精确符号与分数。

## 三、角色接触与独立验收的证据链

交付：role-exposure-ledger.jsonl、role-registration.json、access-boundaries.json、actual-receipts/。

链条是“谁/哪个实际会话 → 何时可见哪些绑定材料 → 是否参与调参或看过其他结论 → 可以承担的角色 → 实际隔离和交付回执”。

- 每个涉及的实际人员/会话登记身份标识、任务、时间、可见材料/权限范围、访问或交付依据；没有记录的部分写UNKNOWN。
- 旧日志缺失时，可把可能接触者保守登记为有上下文/可能已接触，放弃其未曝光资格。无需证明其历史清白；不能把“无日志”写成“未接触”。
- 明确初审A、独立B、冲突C、规则调参者、最终包保管者和最终验证审查角色；B/C尚无真实资源就写PENDING及缺少什么。不得生成虚拟签名、把Claude确认邮件当独立验收，或仅改会话名字宣称独立。
- 提供实际输入包SHA、可见权限/传递记录和真实回执：A/B不互看结论，C不兼任冲突方，最终验证资料不能用于调参。接收记录只证明取得材料，不替代完整访问/隔离范围证明。

文件索引、邮件元数据或邮件正文SHA不能单独证明某个人实际看过/没看过内容。本项目证据也不能证明基础模型预训练从未见过公开真题。

## 四、前三组完成后才需要的执行材料

不是现在要求补造的历史记录；按实际发生顺序产生：

1. qualification-decision.json：逐候选与核心的资格/隔离决定，真实可用数量和依据；不删除原池记录。
2. stage-membership.json、P1/P2 population manifests：校准与最终阶段成员/完整核心族分离，真实有限题对总体、各层数量与分母；在抽样、预测、标注前冻结。
3. sampling-receipt.json、完整盲标包、双方真实标签和实际冲突裁决：按v3随机无放回抽样，不设自然正例配额，不合成新题。
4. fixed-rule.manifest.json、bound-predictions.jsonl、final-statistics.json及原始运行记录：规则/参数/实现固定于最终验证前；两个总体分别满足
\[
\operatorname{FPR}_{U}\le\frac1{100},\qquad
\operatorname{Recall}_{L}\ge\frac{19}{20},
\]
联合覆盖至少 \(19/20\)，真实类别分母有效。仍使用v3精确超几何界，预算上限540/360保持。证据或自然类别不足仍UNCALIBRATED。
