# 交互式体验规划(渲染侧二期)

> 2026-10-05,用户设想定稿:动画生成完毕后——2D 可双指缩放/单指任意拖动;
> 3D 可双指旋转看全貌(GeoGebra 式);另实现参数滑杆;对话式尽量实现
> (视数据需求另定)。不用步骤化观看。

## 0. 核心技术决策(不可回退)

交互**不做在成品视频上**,做在**场景数据重绘**上:
- 对视频做缩放=裁切放大,必糊;对视频做 3D 旋转=不可能(固定投影)。
- 正确路线(GeoGebra 原理):动画播完后保留对象模型(曲线/曲面/点),
  用户手势 → WebGL 实时矢量重绘——任意缩放永远清晰,3D 可任意旋转。
- 我们的管线天然支持:scene_spec 即对象模型,渲染管线持有全部数学对象。

**结论:交互是渲染层工程,几乎不依赖训练。** MP4 路径保留(简单分发),
交互模式为进阶体验。

## 1. 分期与触发条件

### 第一期:自由视角交互(核心设想,零训练改动)
- 渲染管线新增"交互导出"模式:scene_spec → 交互场景数据;
- MathGuide 内嵌 WebGL 查看器:2D 双指缩放/单指拖动、3D 双指旋转
  (Manim OpenGL/ThreeDScene 摄像机体系为原生能力);
- 二次曲面类 3D 交互为工作量最大块,可后置。

**可启动条件(越早越好,由 Claude Code 主动提醒用户)**:
- 渲染管线验收收口(Codex 资产逐条验收进行中或完成后,避免与其渲染侧
  改动冲突),不依赖训练模型——交互导出吃的是 scene_spec,与人写还是
  模型生成无关。

### 第二期:参数滑杆
- 前提:scene_spec 契约扩展显式参数标注(含参对象/表达式/取值范围);
- 训练侧教模型输出参数标注(需一小批带标注样本补充训练)。

**可启动条件**:训练闭环第一轮评测产出后(模型能稳定输出 scene_spec,
再谈参数标注扩展;契约变更须先过 Codex 复验)。

### 第三期:对话式("换 a=2""换更难的例子")
- 独立任务(指令 → scene_spec 修改),与"题目→动画"是两个任务;
- 需指令对数据集,单独训练/评估,不混入当前训练。

**可启动条件**:一期、二期成熟 + 用户拍板投入指令数据生产。

## 2. 与训练主线的关系

- 交互规划不阻塞训练主线,训练照常;
- 唯一会回头碰训练的是第二期(scene_spec 参数标注的小批数据);
- 第三期是独立数据/训练线,按需立项。

## 3. 提醒机制

各期"可启动条件"达成时,由 Claude Code 主动通知用户"可以开始做第 N 期",
越早越好。
